# Using Codex and Claude in My Editor

One of the most valuable changes in my workflow has been using Codex and Claude directly inside my editor. Instead of switching between the codebase, documentation, browser tabs, and a separate chat window, I can keep the conversation close to the files I am working on.

That changes the way I build. When the AI can inspect the project structure, read the relevant files, and understand the surrounding code, the answers become more practical. It is no longer just general advice. It becomes help that is grounded in the actual application.

Codex has been useful when I want to make focused changes inside a repo. I can ask it to inspect how something works, update a component, add a page, fix a route, or run checks after the change. Having it work in the same workspace makes the feedback loop much faster.

Claude has been helpful for thinking through ideas, writing, reviewing, and explaining tradeoffs. I have found it useful when I want a second pass on wording, structure, or the bigger picture of what I am trying to build.

The biggest value is not that these tools replace the work. The value is that they reduce friction. They help me get unstuck faster, see patterns in the codebase, and move from an idea to an implementation with less context switching.

I have also learned that the quality of the result still depends on the quality of the direction. When I give clear context, name the files, describe the outcome, and review the changes carefully, the tools become much more useful.

Using Codex and Claude in the editor has made AI feel less like a separate tool and more like part of the development environment. It helps with writing code, understanding code, documenting work, and keeping momentum while I build.
